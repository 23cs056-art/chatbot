DATABASE NORMALIZATION – COMPLETE KNOWLEDGE

Normalization is the process of organizing data in a database to reduce
redundancy and improve data integrity. The main goal is to ensure that
data is stored efficiently and consistently.

Problems solved by normalization: - Redundancy: Duplicate data stored
unnecessarily. - Insertion anomaly: Difficulty inserting new data. -
Deletion anomaly: Loss of important data when deleting records. - Update
anomaly: Inconsistent data due to multiple copies.

Basic database terms: - Schema: Structure of a database. - Relation:
Table in a database. - Attribute: Column in a table. - Tuple: Row in a
table. - Domain: Set of valid values for an attribute.

Keys in database: - Primary Key: Unique identifier for each record. -
Candidate Key: Possible keys that can become primary key. - Super Key:
Set of attributes that uniquely identify rows. - Composite Key: Key made
of multiple attributes. - Foreign Key: Attribute that links two tables.

Functional Dependency (FD): A relationship between attributes where one
determines another.

Types of dependencies: - Trivial dependency: Attribute depends on
itself. - Non-trivial dependency: Attribute depends on another
attribute. - Full dependency: Attribute depends on whole key. - Partial
dependency: Attribute depends on part of key. - Transitive dependency: A
→ B → C.

Other concepts: - Determinant: Attribute that determines another
attribute. - Closure: Set of attributes derived from a given attribute.

Armstrong’s Axioms: - Reflexive - Augmentation - Transitive

Normal Forms:

1NF (First Normal Form): - Only atomic values. - No repeating groups.

2NF (Second Normal Form): - No partial dependency.

3NF (Third Normal Form): - No transitive dependency.

BCNF (Boyce-Codd Normal Form): - Every determinant is a candidate key.

Higher Normal Forms: - 4NF: Removes multi-valued dependency. - 5NF:
Removes join dependency.

Decomposition: Breaking a table into smaller tables to remove
redundancy.

Properties of decomposition: - Lossless Join: No data loss after
decomposition. - Dependency Preservation: All dependencies are
maintained.

Other important concepts: - Minimal Cover: Simplified set of functional
dependencies. - Table Splitting: Dividing a table into smaller tables. -
Normalization Technique: Step-by-step application of normal forms. -
Normalization Level: Degree of normalization achieved.

Trade-offs: - Advantages: Reduced redundancy, improved consistency. -
Disadvantages: Increased number of joins, possible performance impact.

Denormalization: Combining tables to improve performance when fast data
retrieval is needed.

Database Design Concepts: - ER Model: Entity-relationship model. - Data
Modeling: Designing the structure of a database. - Schema Design:
Structuring database tables. - Database Design Process: Steps to create
a database.

Systems: - OLTP: Online Transaction Processing system. - OLAP: Online
Analytical Processing system.

Optimization Techniques: - Indexing: Improves query performance. - Query
Optimization: Writing efficient queries. - Performance Tuning: Enhancing
database performance.

Integrity Constraints: - Entity Integrity: Primary key must be unique
and not null. - Referential Integrity: Foreign key must match primary
key. - Domain Integrity: Attribute values must be valid.

Final Concept: Normalization focuses on structure and consistency.
Denormalization focuses on performance.

Real-life Example: Student-Course database system.
